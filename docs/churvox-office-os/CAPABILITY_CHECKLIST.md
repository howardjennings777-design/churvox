# Churvox Office OS — Complete Capability Checklist

This checklist prevents the clean rebuild from becoming a good-looking shell with missing business depth.

Legend:

- **Core** — required before replacement cutover
- **Strong** — required to call Churvox a top-tier small-business product
- **Later** — useful after the strong release
- **Excluded** — deliberately outside Churvox

## Product principles

- Core — Churvox does the admin; the owner checks and approves
- Core — Command is the single approval desk
- Core — Nothing important sends, charges, syncs, files, pays or changes financial records without authority
- Core — Every external or financial action is idempotent
- Core — Every important decision is auditable
- Core — Failed actions return visibly with safe retry
- Core — No fake production data
- Core — No competitor names in product copy
- Core — Locked pricing remains unchanged
- Core — Live Render remains untouched until explicit cutover approval

## Cutover definition

Churvox may replace the current live product only when:

1. Every Core item required for the selected launch scope is implemented.
2. Strong items that define the background-office advantage are implemented.
3. Desktop, mobile, offline, permission, billing, migration and rollback tests pass.
4. A real migration rehearsal succeeds without uncontrolled writes.
5. Monitoring and recovery are ready.
6. The owner reviews the replacement and explicitly approves cutover.
